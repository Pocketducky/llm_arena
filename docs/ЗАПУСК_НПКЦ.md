# Запуск системы оценки суммаризаций ЭМК на мощностях НПКЦ (vLLM)

Пошаговая инструкция для оператора. Предполагается, что вы умеете работать в
терминале (команды, `cd`, редактирование текстовых файлов), но не обязаны
разбираться во внутренностях кода. Все команды даны блоками — копируйте целиком.

Система оценивает качество кратких суммаризаций электронных медицинских карт с
помощью ансамбля LLM-судей. Модели крутятся на **вашем** сервере через **vLLM**;
этот код только отправляет им запросы и собирает результаты. Модели локально
ставить не нужно — они уже развёрнуты у вас.

---

## Что понадобится
- Сервер НПКЦ с запущенным **vLLM** и моделями `qwen3.5-122b-fp8`, `qwen3.6-27b-fp8`.
- **Python 3.10+** и `pip` на машине, откуда запускаете код (может быть тот же сервер).
- Сетевой доступ с этой машины до адреса(ов) vLLM.

---

## Шаг 1. Поднять модели в vLLM

vLLM обычно обслуживает **одну модель на один процесс/порт**. Поэтому две модели
запускаются двумя командами на разных портах. Пример (пути к моделям и параметры
железа — ваши; при вопросах по флагам обратитесь к вашему DevOps):

```bash
# Крупная модель — порт 8000
vllm serve /path/to/qwen3.5-122b-fp8 \
  --served-model-name qwen3.5-122b-fp8 \
  --port 8000 \
  --max-model-len 16384
```

```bash
# Средняя модель — порт 8001
vllm serve /path/to/qwen3.6-27b-fp8 \
  --served-model-name qwen3.6-27b-fp8 \
  --port 8001 \
  --max-model-len 16384
```

**Самое важное:** значение `--served-model-name` должно ТОЧНО совпасть с именем
модели в конфигурации (шаг 3). Проверить, под каким именем модель реально
обслуживается, можно так:

```bash
curl http://localhost:8000/v1/models
curl http://localhost:8001/v1/models
```

В ответе поле `data[].id` — это и есть имя, которое надо вписать в конфиг.

> Если у вас перед моделями стоит общий шлюз (один адрес на обе модели) — тогда
> обе модели доступны по одному URL, и отдельные порты не нужны (см. шаг 3).

## Шаг 2. Установить код и зависимости

```bash
git clone <адрес-репозитория> llm_arena
cd llm_arena
git checkout npkc-vllm
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

---

## Шаг 3. Настроить подключение (файл `.env`)

Скопируйте шаблон и откройте `.env` в редакторе:

```bash
cp .env.example .env
```

Впишите ваши значения. Минимум, что нужно проверить/задать:

- `EMR_MODEL_LARGE` и `EMR_MODEL_MEDIUM` — имена моделей **ровно как в `/v1/models`**.
- Адреса vLLM. Два варианта:
  - **Разные порты** (как в шаге 1) — задайте:
    ```
    EMR_VLLM_ENDPOINT_LARGE=http://localhost:8000/v1
    EMR_VLLM_ENDPOINT_MEDIUM=http://localhost:8001/v1
    ```
  - **Один общий адрес/шлюз** — задайте только:
    ```
    EMR_VLLM_BASE_URL=http://localhost:8000/v1
    ```
- `EMR_VLLM_API_KEY` — оставьте `EMPTY`, если vLLM без авторизации.

Остальные параметры (`EMR_TIMEOUT`, `EMR_MAX_TOKENS` и т.д.) можно не трогать —
значения по умолчанию рассчитаны на крупные модели.

Файл `.env` подхватывается автоматически при запуске любой команды.

---

## Шаг 4. Проверить связь (обязательно перед прогоном)

```bash
python check_environment.py
```

Скрипт: (1) проверит, что vLLM доступен; (2) сверит, что модели профиля реально
обслуживаются; (3) отправит по одному тестовому запросу на каждую модель и
покажет ответ. Если всё зелёное (`OK`) — можно запускать. Если где-то `НЕТ` —
скрипт подскажет, что поправить (обычно это несовпадение имени модели).

---

## Шаг 5. Запустить оценку

Основная точка входа — полный прогон корпуса из `data/summaries.xlsx`:

```bash
python run_pipeline.py
```

Что происходит: каждая пара «ЭМК → суммаризация» проходит препроцессор →
объективный слой → шлюз → три раунда LLM-судей → детерминированную агрегацию;
результат пишется в аудит-лог и итоговый Excel.

Полезные варианты запуска:

```bash
# Сначала пробный прогон на 3 парах — убедиться, что всё работает:
python run_pipeline.py --limit 3

# Явно указать профиль моделей (по умолчанию берётся npkc из .env):
python run_pipeline.py --profile npkc

# Прогон без обращения к LLM (проверка проводки/данных):
python run_pipeline.py --limit 3 --dry-run
```

> **Время.** Одна пара — это ~20+ обращений к моделям (3 судьи × 5 блоков + рецензия
> + арбитр). На крупной модели это небыстро; полный корпус идёт долго. Прогон
> **возобновляемый**: промежуточные результаты сохраняются в `checkpoints/`, и
> повторный запуск той же команды продолжит с места остановки (не считает заново
> уже готовые пары). Можно спокойно прерывать и продолжать.

### Дополнительные точки входа (по необходимости)
- **Синтетический стресс-тест** (детекция искажений, если у вас есть файл набора):
  ```bash
  python synthetic.py --mode a --xlsx /путь/к/синтетическому_набору.xlsx --excel-out reports/synthetic.xlsx
  ```
- **Разбор одного пациента синтетики** (ранжирование суммаризаций):
  ```bash
  python eval_patient.py --patient Ж1 --xlsx /путь/к/синтетическому_набору.xlsx
  ```

## Шаг 6. Где результаты
- `reports/` — итоговые Excel-отчёты (сводка по парам, оценки блоков, объективный слой рядом с LLM-оценкой).
- `checkpoints/` — промежуточные результаты по каждой паре (для возобновления).
- `audit_log/` — журнал аудита (JSONL): версии промптов/моделей, решения, снимки для мониторинга дрейфа.
- `*.log` — подробные логи прогона.

Эти папки НЕ попадают в git (содержат фрагменты медицинских данных) — они остаются на вашем сервере.

## Траблшутинг

| Симптом | Что делать |
|---|---|
| `check_environment.py`: бэкенд недоступен | Проверьте, что vLLM запущен и адрес в `.env` верный (`curl <адрес>/v1/models`). |
| В ответе `НЕТ` напротив модели / ошибка 404 | Имя модели в `.env` не совпадает с `--served-model-name`. Сверьте с `/v1/models`. |
| Частые таймауты в логах | Увеличьте `EMR_TIMEOUT` в `.env` (например до 900). Крупная модель под нагрузкой отвечает дольше. |
| Хочется задействовать «мышление» Qwen3 | `EMR_VLLM_ENABLE_THINKING=1` в `.env`. По умолчанию выключено ради надёжности JSON. |
| Прогон прервался | Просто запустите ту же команду снова — продолжит с последнего чекпоинта. |
| Нужен другой набор моделей/ролей | Отредактируйте `EMR_MODEL_LARGE/MEDIUM` или профиль в `config.py`, затем повторите шаг 4. |

Полный список переменных с пояснениями — в файле `.env.example`.
Как устроен сам конвейер оценки — в [АРХИТЕКТУРА.md](АРХИТЕКТУРА.md).
