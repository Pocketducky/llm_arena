## Задача
Прогнать синтетический набор управляемых искажений
`materials/Синтетический_НД_для_тестирования_Сеченовский_университет.xlsx`
(Сеченовский ун-т) через алгоритм оценки, чтобы (а) он ловил внедрённые ошибки и
(б) получить количественную точность по типам искажений. Параллельно — рефакторинг
валидационного контура (сделан). Полный план: `~/.claude/plans/` (на Windows был
`crystalline-seeking-metcalfe.md`) — основное продублировано здесь.

## Почему переехали на Mac
Windows-ПК: RTX 3050 Ti Laptop, 4 ГБ VRAM — qwen3:8b (7.8 ГБ) влезал в VRAM лишь на
~30%, остальное на CPU → ~22 с/вызов LLM. MacBook Air 16 ГБ (unified memory, Metal):
модель помещается целиком → ожидаемо ~8–10 с/вызов, в ~2–3× быстрее.

## Структура набора (ВАЖНО — на этом держится валидация)
Лист `Лист1`, колонка `Unnamed: 0` — метки строк; 10 колонок-пациентов (Ж1..Ж5, М1..М5):
- строка 0 — исходный нарратив ЭМК (~1800-2900 симв.);
- строка 1 — ЭТАЛОННАЯ корректная суммаризация (gold);
- строки 2..38 — та же суммаризация с ВНЕДРЁННЫМИ искажениями, кумулятивный градиент
  серьёзности по тематическим блокам (×1/×2/×3).

**Ключ:** тип искажения в строке N ОДИНАКОВ для всех 10 пациентов → ground truth =
номер строки. Легенда зашита в `synthetic.py::ROW_DISTORTIONS` (редактируемый источник
правды; пограничные строки 21-23, 27, 29-31 помечены дефолтами).

## ОБНОВЛЕНИЕ (сессия на Mac, 2026-06-20) — прогоны + рефакторинг

**Окружение:** venv в repo/.venv (Python 3.14), Ollama с qwen3:8b. На Mac ~30-40 с/вызов
(не 8-10 как ожидалось) — полный режим A (370 пар) идёт ~3 часа.

**Первые прогоны (ДО рефакторинга) — зафиксированная база:**
- Режим A с LLM: critical recall **77.6%**, benign FPR **57.5%** (взрыв из-за шума LLM-сущностей).
- Режим B (1 колонка): **100% reject** по всем строкам (шлюз отклонял всё).

**Диагноз и рефакторинг (фиксы A–E + расширение онтологии):**
- **A. Нечёткое сопоставление сущностей** (`objective_layer._entity_match`): точное/подстрока/
  подмножество токенов/посимвольная близость ≥0.85. Поглощает опечатки/словоформы/расшифровки,
  но оставляет реальные подмены различимыми (зазор 0.77 подмена vs 0.97 опечатка). Устранён
  латентный баг рассогласования matched vs missing/extra.
- **B. Фильтр значимости** (`synthetic._significant_entity`): мусорные/служебные фантомные сущности
  не флагают.
- **C. Режим B: reference `source`→`gold`** (`synthetic.run`). Сверка сжатой суммаризации с полной
  ЭМК при scope=None проваливала шлюз для ЛЮБОЙ суммаризации (включая эталон). Теперь эталон↔
  искажение сопоставимого объёма: benign проходит судей, critical отклоняется.
- **D. Детектор ложной причинности** (`objective_layer.compare_causality`): ловит введённые
  причинные связки («вследствие», «по причине»), к которым слепы остальные сигналы. Узкий набор
  маркеров (без «на фоне/при/после» — дали бы FPR). Временны́е свопы (после↔перед) — на LLM-судьях.
- **E. Фильтр артефактов извлечения** (`objective_layer`): три механизма против недетерминизма
  LLM-извлечения, прокинуты в compare_texts И gate.evaluate_gate (через сырые text_a/text_b):
    1. *cross-text*: «пропавшая» сущность, реально присутствующая в тексте ДРУГОГО документа, —
       промах извлечения, а не пропуск контента (`_entity_present_in_text`);
    2. *self-grounding*: доверяем извлечённой сущности, только если она есть в СВОЁМ тексте —
       LLM додумывает типичные симптомы/показатели (тошнота/одышка к кардиослучаю), которых в
       тексте нет; без фильтра они мерцают между прогонами и дают фантомные missing/extra;
    3. стем-сопоставление (устойчиво к падежам: одышка↔одышку) + игнор обрамляющих слов
       (`_ENTITY_FRAMING_WORDS`: «определение/тест/общий» — экстрактор добавляет их к
       «гемоглобин 115 г/л» → «определение гемоглобина», в тексте этих слов нет).
  Настоящие пропуск/галлюцинация сохраняются (удалённый/выдуманный контент ядра в тексте не найдёт).
- **Онтология сущностей расширена** (`objective_layer.ENTITY_CATEGORIES`): +`symptoms` +`anamnesis`.
  Симптомы/анамнез (боль, наследственность, курение) — частые цели галлюцинаций/пропусков — раньше
  «ловились» только шумом; теперь честно. Обновлён radiologist-фильтр в gate.py.

- **F. Детектор ложной интерпретации** (`objective_layer.compare_interpretations`): ловит оценочное
  слово при числе, ПРОТИВОРЕЧАЩЕЕ референсному диапазону («снижено (150/90 мм рт. ст.)» — это
  гипертензия). Отделяет critical `ложная_интерпретация` от benign `интерпретация_норма` (корректная
  оценка согласована с диапазоном → не флагается). Диапазоны консервативны, только для однозначных
  по единице величин (АД-пара, ЧСС, гемоглобин, креатинин, явный избыток ферментов); ед/л-126,
  ммоль/л, pH — неоднозначны, пропускаются (отданы судьям). Подключён в synthetic (сигнал
  «интерпретация») и в judge заземление блока A. Rule-based эффект: ложная_интерпретация 37%→80%,
  benign FPR без изменений (0 ложных на интерпретация_норма).

- **G. Надёжность JSON у судей** (`judge.py`): в раундах R1/R2/R3 включён `think=False` —
  скрытые `<think>`-рассуждения qwen3:8b съедали бюджет `num_predict` и обрывали большой JSON
  (особенно полный отчёт A-E в R2: «B2/E3 нет валидного pass» → 3 провальные попытки → откат к R1).
  Плюс R2 переведён на **толерантный мердж** (`_merge_full_report`): ответ модели накладывается на
  валидный отчёт R1, обрыв/пропуск поля больше не фатален — R2 НИКОГДА не падает (худший случай =
  R1). num_predict поднят для R2 (2048) и R3 (1536). Судьи стали быстрее (нет скрытых рассуждений +
  нет бесполезных ретраев). Затрагивает весь прод-конвейер (run_pipeline.py).
- **H. Калибровка gate под общие суммаризации** (`gate.py`, `_entity_recall_reasons` scope-aware):
  при `scope=None` (сжимающая сводка vs полный исходник) gate блокировал ЛЮБОЕ покрытие <50% по любой
  категории — и отклонял ВСЕ сводки (включая эталон), т.к. departments/symptoms закономерно не
  покрыты. Теперь при scope=None reject ТОЛЬКО при полном отсутствии клинически критической категории
  (`CRITICAL_ENTITY_CATEGORIES` = диагнозы/препараты, recall==0); прочее — закономерная компрессия,
  полноту оценивают судьи (блок B). При `scope!=None` (целевая выжимка) — прежняя логика, прод не
  затронут. Эталон → pass, вырожденная сводка → reject.

Все юнит-проверки в objective_layer/synthetic self-check зелёные. v2-прогон (до Fix F):
reports/synthetic_modeA_v2.xlsx, synthetic_modeB_v2.xlsx. Fix F-H добавлены ПОСЛЕ v2 — для полного
эффекта нужен re-run.

## Финальный сквозной тест одного пациента (eval_patient.py)
`python eval_patient.py --patient Ж1` — прод-сценарий «дан исходник ЭМК и набор суммаризаций,
выбери лучшую»: каждая из 38 сводок (эталон + 37 искажённых) сверяется с ИСХОДНИКОМ через gate +
3-раундовых судей; ранжирование, поиск лучшей (ожидаемо — эталон стр.1). Отчёт reports/eval_patient_*.xlsx,
лог .log, чекпоинты checkpoints/eval_patient/ (с возобновлением). Не отслеживается git (аналитический
скрипт). Флаги: `--representative` (17 строк: эталон + по 1 представителю каждого типа),
`--recompute-objective` (пересчёт объективного слоя при переиспользовании судей), `--report-only`.
ВАЖНО: запускать под `caffeinate -i` — иначе сон Mac вешает прогон (таймаут не срабатывает во сне).

**РЕЗУЛЬТАТ (финальный прогон 17 строк, профиль pilot):** эталон → 1-е место ✓; gate 17/17 pass;
0 сбоев JSON за ~15 ч. Дискриминация шумная (предел 8B): жёстко отклонены 3/8 critical-типов, 5 слиты
с эталоном, 2 benign ложно отклонены, вердикты недетерминированы между прогонами. Полный разбор —
**REPORT.md** (итоговый отчёт о пилоте).

**Честное ограничение дизайна:** объективный слой (режим A) НЕ берёт тонкую семантику —
ложная_интерпретация («повышена» к норм. значению), временны́е свопы, — это сознательно отдано
LLM-судьям (режим B). Цель ≥90% critical recall — для всего стека, не для объективного слоя в одиночку.

## После прогонов — что оценить
- Режим A: вырос ли recall по подмена_сущности/галлюцинация/пропуск_контента за счёт
  сигнала «сущности»; не подскочил ли benign FPR (LLM-извлечение шумит). Цель дизайна:
